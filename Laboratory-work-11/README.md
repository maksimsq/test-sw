### 2.1 Теоретичне завдання зі створення історій виконання транзакцій

Завдання 2.1.1
Створити історію квазіпаралельного успішного виконання транзакцій для протоколу 1-го ступеня блокування.
Транзакції:
T1 = R1[A], W1[A], C1  
T2 = W2[A], R2[B], W2[B], C2  
T3 = R3[D], R3[B], W3[D], C3

Опис операцій:

R[X] — читання значення змінної X  
W[X] — запис нового значення в змінну X  
C — завершення транзакції (COMMIT)
X[X] — запит на виключне блокування змінної X
U[X] — зняття блокування зі змінної X

Історія виконання транзакцій для протоколу 1-го ступеня блокування:
H(T1,T2,T3) = X1[A] R1[A] W1[A] 
              X2[A]-Wait 
              C1 U1 
              X2[A] W2[A] X2[B] R2[B] W2[B] 
              X3[D] R3[D] X3[B] R3[B] 
              W3[D] 
              C2 U2 
              C3 U3

Завдання 2.1.2
Описати таблицю блокування транзакцій до моменту першої фіксації (тобто до C1):
H(T1,T2,T3) = X1[A] R1[A] W1[A] 
              X2[A]-Wait

char* lock_table[][3] = {
    { "A", "X1", "-" }
};

Завдання 2.1.3
Для створеної історії визначити наявність Deadlock-стану транзакцій, створити граф очікування.
int wait[1][2] = {
    { 2, 1 } // T2 чекає T1
};

Висновок:На основі побудованого графа очікування транзакцій встановлено, що він не містить циклів, отже, Deadlock-стан транзакцій відсутній.
Завдання 2.1.4
Повторити завдання 2.1.1, але для протоколу 2-го ступеня блокування.
Транзакції:
T1 = R1[A], W1[A], C1  
T2 = W2[A], R2[B], W2[B], C2  
T3 = R3[D], R3[B], W3[D], C3

Історія виконання транзакцій для протоколу 2-го ступеня блокування:
H(T1,T2,T3) = X2[A] W2[A] X2[B] R2[B] W2[B] 
              C2 U2 
              X1[A] R1[A] W1[A] 
              C1 U1 
              X3[D] R3[D] X3[B] R3[B] 
              W3[D] 
              C3 U3

Завдання 2.1.5
Визначити наявність Deadlock-стану транзакцій для історії протоколу 2PL.
int wait[0][2] = {};

Висновок:У графі очікування транзакцій немає циклів, отже, Deadlock-стан транзакцій відсутній.

2.4.2 Виконати модифіковані транзакції. Проаналізувати реакцію СКБД на операцію зміни значення стовпчика для транзакції, яка виконувалася пізніше (призвела до Deadlock-стану), та надати висновки за результатами аналізу з урахуванням ідентифікаторів процесів та номерів транзакцій.
Висновок: Я створив ситуацію, де дві транзакції блокували один рядок і намагались змінити інший, вже заблокований. В результаті виник deadlock — система це виявила і автоматично скасувала одну з транзакцій. Це показує, що PostgreSQL правильно визначає та вирішує конфлікти при взаємному блокуванні.
