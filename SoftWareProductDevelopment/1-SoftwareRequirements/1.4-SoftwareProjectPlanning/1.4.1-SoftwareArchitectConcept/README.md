### 1.4.1-SoftwareArchitectConcept
### Концептуальний опис архітектури програмного продукту

Архітектура програмного продукту **SliderAR** побудована на трирівневій (3-Tier) архітектурній моделі, що забезпечує чіткий поділ між інтерфейсом, бізнес-логікою та даними.

#### 1. Рівні архітектури та компоненти
- **PL (Presentation Layer - Рівень представлення):**
  - *Компоненти:* Модуль графічного інтерфейсу (GUI) та компонент захоплення відеопотоку.
  - *Технології:* Python, OpenCV (для виведення вікна візуалізації), Tkinter або PyQt (для панелі керування).
- **BL (Business Logic Layer - Рівень бізнес-логіки):**
  - *Компоненти:* Детектор маркерів ArUco, модуль розрахунку лінійного положення повзунка, контролер налаштування обладнання.
  - *Технології:* Python, OpenCV ArUco Module, NumPy.
- **AL (Access Layer - Рівень доступу до даних):**
  - *Компоненти:* Менеджер збереження конфігурації та параметрів системи.
  - *Технології:* JSON-файли конфігурації / локальне сховище.

#### 2. Зв'язки між компонентами
- **Передача даних:** Відеопотік передається від камери до PL $\rightarrow$ кадри надходять у BL для аналізу $\rightarrow$ розраховані координати та відсоток положення передаються назад у PL для відображення $\rightarrow$ збережені параметри надходять до AL.
- **Передача управління:** Користувач через PL ініціює старт камери чи зміну налаштувань $\rightarrow$ BL обробляє події детекції $\rightarrow$ AL записує стан на диск.
